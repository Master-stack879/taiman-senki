# 無限回廊 オンラインランキング（サーバー側の準備）

ランキングの受け皿（Firebase の Cloud Firestore）の設定と確認用のファイルです。ゲーム本体（`index.html`）への組み込みは済んでいます（docs/冒険モード設計方針.md の「オンラインランキング」）。

| ファイル | 内容 |
|---|---|
| `firestore.rules` | サーバー側の入力チェック（Firebase コンソールの「ルール」に貼る） |
| `firestore.indexes.json` | 上位を並べるための複合インデックスの定義（手順7で作るものと同じ） |
| `test.html` | 本番プロジェクトで送信・読み出し・弾かれるかを試すページ |
| `test/rules.test.mjs` | ルールの自動テスト（Firestore エミュレーター） |
| `test/page.test.mjs` | `test.html` をエミュレーター相手にブラウザで操作する自動テスト |
| `test/game.test.mjs` | ゲーム本体（`index.html?rank-emulator`）の無限回廊ランキングをエミュレーター相手に操作する自動テスト |
| `firebase.json` / `package.json` | エミュレーターとテストの設定 |

## サービス：Cloud Firestore（Firebase の Spark プラン＝無料）

| 観点 | Firestore（Spark） | Supabase（Free） |
|---|---|---|
| 使わない期間に止まらないか | 止まらない。無料枠を超えた日はその日だけ使えなくなる | **1週間アクセスが少ないと一時停止**。再開は管理画面から手で行う。停止中はランキングが読めない |
| GitHub Pages から直接使えるか | 使える（公式 SDK を CDN から読む） | 使える |
| サーバー側の入力チェック | セキュリティルールで項目・型・長さ・範囲・時刻を検査できる | Postgres の制約と RLS で検査できる（こちらも十分強い） |
| 連続投稿よけ | ルールの `request.time` と `getAfter()` で端末ごとの間隔を強制できる | トリガー関数を SQL で書けば可能 |
| 手間 | 画面操作だけで完結。サーバーの保守なし | SQL を書いて流す作業がある。停止の監視が要る |
| 無料枠 | 保存 1 GiB、読み取り 5万/日、書き込み 2万/日、削除 2万/日。カード登録不要 | DB 500 MB（1プロジェクトあたり）、稼働中2プロジェクトまで |

この用途は「投稿が数日ないこともある、小さな趣味のランキング」なので、Supabase の1週間で一時停止は致命的です。Firestore を選びました。

**無料枠の目安**：投稿1回で書き込み2件（記録＋連続投稿よけ）なので 1日 1万回まで。上位20件の表示1回で読み取り20件なので 1日 2,500回まで。ゲーム側ではランキング画面を開いたときだけ読み、件数は 20〜50 件にしてください。

## データの形

コレクション `scores` に1記録1ドキュメント（ID は自動）。

| 項目 | 型 | 内容 | ルールでの検査 |
|---|---|---|---|
| `name` | 文字列 | 名前 | 1〜12文字（JS の `length` と同じ数え方。絵文字は2と数える）、空白だけは不可 |
| `char` | 文字列 | キャラ | `kai` `mira` `gard` `rin` `shizuku` `doran` のどれか |
| `floor` | 整数 | 到達階 | 1〜200（小数・文字列は不可） |
| `at` | タイムスタンプ | 日時 | サーバーの時刻（`serverTimestamp()`）のみ。端末の時計は使えない |
| `ver` | 文字列 | ゲームのバージョン | 1〜16文字 |

この5項目以外が入っていても、足りなくても弾きます。

### 連続投稿よけ

- ゲームは記録を送るときに Firebase の**匿名ログイン**をします（名前やメールは不要。ブラウザに匿名の ID が保存されるだけ）。
- 記録を送るときは、`scores` への追加と `limits/{匿名ID}`（中身は最終投稿時刻 `last` だけ）の更新を**1回の一括書き込み**で行います。
- ルールは「`limits` の更新とセットでないと記録を追加できない」「前回から60秒経っていないと `limits` を更新できない」を強制します。秒数は `firestore.rules` の `cooldownSec()` で変えられます。
- `scores` の記録には匿名 ID を入れません（送るのは上の5項目だけ）。`limits` は誰も読めません。
- 限界：ブラウザのデータを消す・シークレットウィンドウを使うと新しい ID になるので、同じ人の連打をおさえる仕組みであって、悪意のある大量投稿を完全には止められません。必要になったら App Check（ボット対策）の追加を検討します。

### 読み出し

誰でも読めます（ログイン不要）。1回に読めるのは100件まで。上位は「到達階の高い順、同じ階なら先に達成した順」：

```js
query(collection(db, 'scores'), orderBy('floor', 'desc'), orderBy('at', 'asc'), limit(20))
```

記録の変更・削除・同じ ID への上書きは、誰もできません（管理画面からの操作は除く）。

## 画面で行う作業（個人の Google アカウントで）

ブラウザは、会社のアカウントでログインしていないプロファイル（またはシークレットウィンドウ）を使ってください。各画面の右上のアイコンが個人アカウントになっているか、毎回確認してください。

1. **Firebase にログイン**
   <https://console.firebase.google.com/> を開き、個人の Google アカウントでログインする。初回は利用規約に同意する。
2. **プロジェクトを作る**
   「プロジェクトを作成」→ プロジェクト名（例：`taiman-senki`）を入れて続行。
   Google アナリティクスは**オフ**にして（不要）作成。料金プランは **Spark（無料）のまま**。Blaze へのアップグレードやカード登録はしない。
3. **Firestore を作る**
   左メニュー「構築」→「Firestore Database」→「データベースの作成」。
   - エディション：**Standard**（Enterprise は選ばない）
   - データベース ID：`(default)` のまま（無料枠が付くのは default の1つだけ）
   - ロケーション：`asia-northeast1`（東京）。※あとから変えられない
   - 「**本番環境モード**で開始」を選んで作成
4. **ルールを入れる**
   Firestore の「ルール」タブを開き、中身を全部消して `firestore.rules` の内容を貼り付け、「公開」。
5. **匿名ログインを有効にする**
   左メニュー「構築」→「Authentication」→「始める」→「Sign-in method」タブ →「匿名」→ 有効にして「保存」。
6. **ウェブアプリを登録して接続設定を取り出す**
   左上の歯車 →「プロジェクトの設定」→「全般」タブ下の「マイアプリ」→ ウェブ（`</>`）アイコン。
   ニックネーム（例：`taiman-senki-web`）を入れ、「Firebase Hosting も設定する」は**チェックしない**で「アプリを登録」。
   表示された `const firebaseConfig = { ... }` の `{` 〜 `}` をコピーしておく（あとでこの画面から何度でも見られる）。
7. **テストページで動作確認し、インデックスを作る**
   - `test.html` を開く（このブランチを main に取り込んだ後なら `https://master-stack879.github.io/taiman-senki/ranking/test.html`。手元なら `npx http-server ranking` などで `http://localhost:8080/test.html`）。
   - 「1. 接続設定」に手順6の内容を貼って「接続する」→「接続しました」と出ればOK。
   - 「4. 弾かれるはずのデータを試す」→ すべて「○ 弾かれた」になることを確認（記録は増えません）。
   - 「2. 記録を送る」→「送信できました」。
   - 「3. 上位20件を読む」→ 初回は「インデックスを作成する」リンクが出るので押す。Firebase コンソールが開くので「インデックスを作成」→ 数分待って状態が「有効」になったら、もう一度「上位20件を読む」。
     （手で作る場合：Firestore「インデックス」タブ →「複合」→「インデックスを作成」、コレクション `scores`、`floor` 降順＋`at` 昇順、クエリのスコープ「コレクション」）
   - 「4」をもう一度押すと、記録の変更・削除も弾かれることまで確認できる。「2回続けて送る」で連続投稿よけも確認できる。
8. **テストの記録を消す**（下の「管理」の手順で）

### 任意：API キーの利用元をしぼる

必須ではありません（安全性はルールで守っています）が、他サイトに設定を流用されにくくなります。
<https://console.cloud.google.com/apis/credentials> で同じプロジェクトを選び、「Browser key (auto created by Firebase)」→「アプリケーションの制限」で「ウェブサイト」を選び、`https://master-stack879.github.io/*` と `http://localhost:*/*` を追加して保存。

## 管理：不適切な名前の記録を消す

管理画面からの操作にはルールがかからないので、ここからは消せます。

1. Firebase コンソール →「Firestore Database」→「データ」タブ
2. `scores` を開く。名前で探すときは、一覧の上の絞り込み（じょうごのアイコン）で「`name` ＝ 探したい名前」
3. 消したい記録をクリック → 右側の縦3点メニュー →「ドキュメントを削除」→ 確認して削除

`limits` の中身（端末ごとの最終投稿時刻）は消さなくてかまいません。

## ゲームに組み込むときに必要な情報

- **接続設定**（手順6の `firebaseConfig`：`apiKey` `authDomain` `projectId` `storageBucket` `messagingSenderId` `appId`）
  → **公開して問題ありません。** Firebase のウェブ用設定は、ページのソースに書く前提の「どのプロジェクトにつなぐか」の識別子で、秘密の鍵ではありません。守っているのは `firestore.rules` です。`index.html` にそのまま書いてかまいません。
  → **公開してはいけないもの**：サービスアカウントの秘密鍵（JSON）と Google アカウントのパスワード。今回の構成ではサービスアカウント鍵は作らないし使いません。
- **SDK**：`https://www.gstatic.com/firebasejs/12.19.0/` の `firebase-app.js` `firebase-auth.js` `firebase-firestore.js`（ES モジュール。`index.html` 側は `<script type="module">` か `import()` で読む）
- **送り方**：`test.html` の `submit()` と同じ（匿名ログイン → `scores` の追加と `limits/{uid}` の `{ last: serverTimestamp() }` を一括書き込み）。名前はゲーム側でも 1〜12（`length`）に切り、空白だけなら送らない。投稿は1回の冒険につき1回。
- **送信失敗**：`permission-denied` は入力チェックか連続投稿よけで弾かれたもの。ネットにつながらないときもゲームの進行は止めない。
- **バージョン文字列**：ゲーム側で定数を1つ決める（16文字以内）。

## 自動テストの実行（開発用）

Java 11 以上と Node.js が必要です。

```sh
cd ranking
npm install
npm test            # ルールのテスト（11項目）
npm run test:page   # test.html をブラウザで操作するテスト（Playwright）
npm run test:game   # ゲーム本体のランキング（名前・1回だけ送る・オフライン）をブラウザで操作するテスト
```

`npm run emulators` でエミュレーターを立てて、`test.html?emulator` を開くと手元で試せます（接続設定は `{ apiKey: "demo-key", projectId: "demo-taiman" }` でよい）。
