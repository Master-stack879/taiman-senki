# tools：バランス調整用の自動プレイ

`index.html` の戦闘エンジンと冒険のデータ部分（`const CHARS` 〜「ローグライト：画面」の手前）を Node で読み込み、画面なしで自動プレイします。ブラウザも依存パッケージも要りません（Node 18 以上）。

すべてリポジトリのルートで実行します。引数は `--名前=値` の形です。乱数は種つきなので、同じ引数なら毎回同じ結果になります。

| コマンド | 調べること | 1回の所要時間の目安 |
|---|---|---|
| `node tools/versus.js` | 対戦モードの総当たり（36通り×1万戦） | 約1分 |
| `node tools/rogue.js` | 3難易度の方針別クリア率・キャラ別クリア率・負けた階 | 約3分（`--n=3000`） |
| `node tools/endless.js` | 無限回廊の到達階 | 約2分（`--n=1000`） |
| `node tools/progress.js` | 全強化までの冒険回数 | 約1分（`--n=2000`） |

## 共通の引数
- `--html=パス`：読み込む index.html（既定はリポジトリの `index.html`）
- `--compare=比べる相手`（versus / rogue）：同じ種で相手の版と結果が完全一致するかを調べる。`git:origin/main` のように書くと、その版の index.html を git から取り出して使う。一致しなければ終了コード1
- `--seed=数`：乱数の種

## 報酬の選び方（方針）
| 名前 | 意味 |
|---|---|
| `random` | ランダム |
| `heal` | 常に回復（回復が無ければランダムな強化） |
| `up` | 常に強化 |
| `hp` | HPを見て選ぶ：HP40%未満、または次がボスでHP60%未満なら回復。それ以外は強化（強化どうしはランダム） |
| `prio` | HPを見て選ぶ（優先順位版）：回復の判断は `hp` と同じ。強化どうしは 体力→攻撃→技→防御 の順 |

- 引き直し（永続強化）は `hp` / `prio` だけが使う：回復したいのに回復が無いとき。
- 無限回廊の休憩所：`hp` / `prio` は HP60%未満なら休む、それ以外は強化。
- 技選びは自分が `cpuChoose`、敵は `rgFoeChoose`（難易度の `ai` の確率で考えて選ぶ）。

## versus.js：対戦モードの総当たり
```
node tools/versus.js                              # 36通り×1万戦
node tools/versus.js --compare=git:origin/main    # main と完全一致するか（エンジン・共通部分を触ったら必ず）
node tools/versus.js --n=1000                     # 回数を減らして手早く
```
- 組み合わせごとに同じ種（1000＋組み合わせの番号）。両者 `cpuChoose`。
- 表は「行のキャラ（A）が列のキャラ（B）に勝つ割合」。最後の「指紋」は全結果のハッシュで、これが同じなら結果は完全に同じ。

## rogue.js：難易度の方針別クリア率
```
node tools/rogue.js                                       # 3難易度×5方針、永続強化なし、キャラごと3000回
node tools/rogue.js --meta=full                           # 全強化の状態
node tools/rogue.js --diff=hard --pol=hp,prio --n=1000    # 難易度・方針・回数をしぼる
node tools/rogue.js --n=300 --compare=git:origin/main     # 既存の難易度の動きが変わっていないか
```
- `--diff`：`easy` / `normal` / `hard`（カンマ区切り）。`--pol`：上の方針（カンマ区切り）。`--meta`：`none`（既定）か `full`。`--n`：キャラごとの回数。
- 結果の見方：
  - `クリア`：踏破の割合。目標は やさしい 70〜80%、ふつう 40〜50%、むずかしい 10〜20%（`hp`・永続強化なし）。
  - `キャラ別`：各難易度の目標の±10ポイント以内か。
  - `負けた階`：負けのうち何階で負けたか。ふつう・むずかしいは4Fが20%以上。
  - `HPを見て選ぶ − 次点`：`hp` と、`random` / `heal` / `up` の最も高いものとの差。5ポイント以上。
- `--compare` は冒険の中身（階・HP・レベル・選んだ報酬・能力・ターン数）まで比べる。「永続強化なしのときは乱数の使い方も含めて前と同じ」の確認に使う。

## endless.js：無限回廊の到達階
```
node tools/endless.js                                   # 全強化、5方針、キャラごと1000回
node tools/endless.js --pol=hp,prio --meta=none         # 永続強化なし
node tools/endless.js --pol=hp,prio --n=200 --set='{"m0":0.55,"eliteMul":1.5}'   # 値を一時的に変えて試す
```
- 到達階＝負けた階（200階を踏破したら200）。`--set` は `RG_ENDLESS` に上書きする値（JSON。index.html は変えない）。
- 結果の見方：
  - `到達階 平均`：目標は全強化・`hp` で 15〜20階。
  - `上位10%の境目` / `上位10%の平均`：目標は全強化・`prio` で 30〜40階。
  - `分布`：10階ごとの割合。`キャラ別平均`：キャラ差。
  - `負けた場所`：魔物・強敵・ボスのどこで負けたか。`戦魂`：1回あたりの平均（上限30）。
  - `1回のプレイ時間の目安`：演出1行0.65秒（突進0.45秒）・決着0.6秒は index.html の値、技選び1ターン2秒・1戦ごとの画面8秒・休憩所4秒は仮定。

## progress.js：全強化までの冒険回数
```
node tools/progress.js                    # むずかしい踏破後は無限回廊で遊ぶ
node tools/progress.js --endless=0        # むずかしいを続ける（回廊が無かったころの遊び方）
node tools/progress.js --pol=prio         # 優先順位版で遊ぶ
```
- 遊び方：使えるキャラからランダムに選ぶ。戦魂が貯まったら安い強化から買う。難易度は解放されたら次へ進む。
- 結果の見方：`全強化までの冒険回数` の目標は 15〜20回。`1人あたりの冒険回数` はどの難易度で何回遊んだか。

## 中身
- `lib/load.js`：index.html の読み込みと、種つきの乱数（`Math.random` を差し替え）
- `lib/play.js`：1回の冒険の自動プレイと方針
- `lib/source.js`：`git:<ref>` の index.html を取り出す
- `lib/args.js`：引数の読み取り

index.html の「ローグライト：データと計算」の範囲に新しい関数を足したら、使う場合は `lib/load.js` の `NAMES` にも足してください。
