# タイマン戦記 オンライン対戦のサーバー化

最終更新：2026-10-20（Firestore 方式で実装）

## やりたいこと（Master 決定）
- ルームコードなしで相手を探せる（ランダムマッチ）。
- ホストが抜けても対戦が続く。

## 今の仕組み
- 前（〜2026-10-20）：PeerJS でブラウザ同士を直接つなぎ、ホストのブラウザが戦闘を計算していた。ホストが抜けると全員の対戦が終わった。**PeerJS の方式は全部置き換え、ページから PeerJS を外した。**
- 今：対戦の状態（キャラ・選んだ技・盤面・ターン・名前）をサーバーのデータベース（Firestore、ranking/ と同じプロジェクト）に置く。プレイヤーと観戦者は全員そのデータを見る。特定の人のブラウザに依存しない。

## 方式：B（状態はデータベース、計算はプレイヤーのブラウザ）
- A. サーバー側で戦闘を計算する（Cloud Functions など）：Firebase では従量課金プラン（クレジットカード登録）が必要なので使わない。
- **B. 採用**：状態はデータベースに置き、計算はプレイヤーのブラウザで行う。
  - 両者が技を選んだら、先に気づいた方のブラウザが計算して書き込む。二重計算はトランザクションで防ぐ（A はすぐ、B は1.5秒待ってから試す。A がいれば B は結果を受け取るだけ）。
  - どちらかが抜けても、残った方が計算を続けられる。再読み込みしても続きから戻れる。
  - 無料枠（Spark）の範囲で作れる。計算結果は理論上その試合のプレイヤーが書き換えられるが、ルールで盤面の範囲（HP・MP）と決着の整合を確かめ、露骨な書き換えは弾く。第三者・観戦者は書き換えられない。

## 決めたこと（2026-10-20 Master 決定）
- **切断したとき**：常時の生存確認はしない。1ターンの期限（技を選ぶ60秒＋演出10秒＝70秒）までに技を選ばなければ、選んだ側の不戦勝（両者とも選ばなければ引き分け）。切断と放置をまとめて扱う。期限を過ぎたかどうかはサーバーの時刻でルールが判定する。残り時間は画面に出す。
  - 比べた案：生存確認の書き込み（15秒ごと）は読み書きが約2倍になる。Realtime Database の切断検知は別サービスと別のルールが要る。今の規模では期限方式で十分。
  - 両者の技がそろっているのに計算されないまま期限を過ぎた試合は、時間切れにせず、戻ってきたどちらかが計算して続ける。
  - 対戦中の「降参して退出する」は、その場で相手の勝ち（降参）。ページを閉じただけのときは期限切れで決着する（再読み込みで戻れるように、閉じたときには降参にしない）。
- **ランダムマッチの相手**：URL を知っている全員から探す。60秒見つからなければ「CPUと対戦する？」を案内する（同じキャラで CPU 対戦／もう一度探す／やめる）。
- **ルームコードで友達と遊ぶ機能**：同じ仕組みで作り直した。ホストはいない（1P・2P の2席。両者がキャラを選ぶと始まり、再戦は両者が「再戦する」を押すと始まる）。
- **観戦と勝敗予想**：同じ仕組みに移した。観戦できるのはルームの対戦だけ。観戦人数の表示はやめ、勝敗予想の票数を出す。
- **名前**：ランキングと同じ禁止語チェック・文字数制限（`rkCheckName`、ルールでも1〜12文字・空白だけ不可）を通し、必ず文字として表示する（`textContent`）。名前の欄はランキングと共通（`taiman-senki:rogue-name`）。
- **相手の技を先に見られない**：相手の技は、自分が同じターンの技を書いたあとでないと読めない（ルール）。観戦者は技を読めない（「選択済み」の印だけ見える）。

## データの形（Firestore）
| コレクション | 中身 |
|---|---|
| `matches/{自動ID}` | 試合1件：`kind`（`random`/`room`）・`room`・`p`（両者の匿名ID）・`names`・`chars`・`st`（盤面 `{turn, A, B}`）・`turn`・`ready`（技を選んだターン。中身は入れない）・`log`（直前のターンの演出。JSON 文字列）・`lt`（`log` のターン）・`tt`（ターン開始のサーバー時刻。期限は `tt`＋70秒）・`at`・`over`（`A`/`B`/`draw`/`void`）・`end`（`ko`/`timeout`/`left`/`cancel`）・`here`（ランダムマッチの参加確認） |
| `matches/{id}/picks/{A\|B}` | 選んだ技 `{turn, idx}` |
| `matches/{id}/preds/{匿名ID}` | 勝敗予想 `{side}` |
| `rooms/{コード}` | ルーム：`seats`・`names`・`chars`・`ready`（準備）・`mid`（今の試合）・`at`（最後に動きがあった時刻） |
| `queue/{匿名ID}` | ランダムマッチの待ち行列 `{name, char, at, mid}` |

- 期限は「サーバーの時刻＋秒数」を書けない（端末から時刻の足し算は送れない）ので、開始時刻だけを持ち、期限はルールとゲームの両方で「開始時刻＋秒数」として計算する。
- 秒数：ゲームは `ON_TURN_SEC`（70）・`ON_SHOW_SEC`（10）・`ON_QUEUE_SEC`（60）・`ON_HERE_SEC`（15）、ルールは `turnSec()`・`queueSec()`・`hereSec()`。**同じ値にそろえる**（ルールは Firebase コンソールに貼り直す）。

## ルール（ranking/firestore.rules）
- 試合：誰でも1件ずつ読める（観戦）。一覧は不可。書けるのは `p.A` / `p.B` の2人だけで、操作ごとに変えてよい項目を限る。
  - 技の印（自分の側の `ready` だけ。同じ一括書き込みでそのターンの技を書くこと）
  - 計算（両者の技がそろっていること。ターンはちょうど1つ進む。盤面は HP 0〜最大HP・MP 0〜最大MP・状態の値の範囲・キャラは変えない。決着は HP と合っていること。キャラの最大値はルールに定数で持つ。`CHARS` の基本値を変えたらルールも直す）
  - 時間切れ（期限後・選んだ側だけが勝ちにできる・そろっていたら不可）、降参（相手の勝ちだけ）、ランダムマッチの参加確認と取り消し
- 技：本人だけが、期限内に、1ターン1回書ける。相手の技は自分が同じターンの技を書いたあとだけ読める。
- 予想：ルームの対戦の観戦者だけ（プレイヤー不可）、1人1件、1ターン目の決着まで。
- 待ち行列：本人だけが作る・消す。相手（後から来た人）は、試合を作る一括書き込みの中で `mid` を入れることだけできる。候補になるのは入ってから60秒まで。
- ルーム：コードを知っている人は読める（一覧不可）。空いた席に座る・自分の席の名前とキャラと準備を変える・席を立つ・戻らない相手を外す（試合が終わっているとき）・両者の準備がそろったら次の試合を作る。最後に動きがあってから2時間で期限切れ（同じコードを新しいルームに使える）。

## マッチングの流れ（ランダム）
1. 名前を入れ、「相手を探す」→ キャラを選ぶと `queue/{自分}` に入る。
2. 10秒ごとに、入ってから60秒以内の待ち行列を最大10件読み、**自分より先に入った人**がいれば自分が試合を作る（後から来た側が作る決まりで、両者が同時に作り合わない）。試合の作成・相手の `mid` の設定・自分の待ち行列の削除はトランザクションで行い、二重割り当てを防ぐ。
3. 割り当てられた側は参加を確かめ（`here.B`）、対戦へ。15秒以内に確かめなければ、作った側が取り消して探し直す。
4. 60秒たっても見つからなければ「CPUと対戦する？」。

### 待ち行列にページを閉じた人が残り続けない
- 候補になるのは入ってから60秒まで（ルールでも強制）。閉じたページは60秒で候補から外れる。生存確認の書き込みは要らない。
- 閉じた直後の人と組まされても、参加確認（15秒）が来なければ取り消して探し直す。
- 待ち行列の ID は匿名ID なので1つのブラウザにつき1件まで。ページを閉じるときも消そうとする（届かないこともある）。残ったデータは小さく、TTL は Spark では使えないので、気になったら管理画面から消してよい。

## 再読み込み・一時的な通信切れからの復帰
- 参加中の試合・ルームを localStorage（`taiman-senki:online`：`{v:1, kind, side, mid, room}`）に置く。読み書きは `lsGet` / `lsSet`。
- ページを開いたときに保存があれば、試合（ルーム）がまだ続いていて自分の席かを確かめ、「対戦に戻る」（「ルームに戻る」）を出す。押すと今の盤面から再開する（自分が選び済みなら、その技を読み直して待つ表示に）。決着済み・席が外れていれば保存を消す。
- 匿名ログインの情報が消えた（シークレットウィンドウを閉じたなど）場合は戻れず、期限切れで決着する。
- 一時的な通信切れは、Firestore の SDK が自動でつなぎ直す。その間は「通信が切れています」と出す。技の書き込みはサーバーに届くまで「送信中」。期限後に届いて弾かれたら理由を出す。戻ったときにターンが1つ進んでいれば演出を再生し、2つ以上進んでいれば盤面だけ合わせる。

## 画面
- モード選択：「オンライン対戦」は最初から押せる（PeerJS の読み込み待ちはなくなった）。続きの試合があれば説明文で知らせる。
- オンライン画面：名前の欄、「相手を探す」（キャラ選択 → 探している秒数 → 60秒で CPU 対戦の案内）、「ルームを作る」「コードで参加」（5文字のコード・`?room=` の招待URL は前と同じ）、「対戦に戻る」。
- ロビー：1P・2P の名前とキャラと準備の状態、自分の席。「戻ってこない相手をルームから外す」。観戦者は「対戦相手として参加する」（席が空いたとき）。
- 戦闘画面：名前（文字として表示）、残り時間（残り10秒で強調）、通信状態、勝敗予想の票数（観戦人数の代わり）。
- 結果：時間切れの不戦勝・降参の理由。ランダムマッチのあとは「もう一度相手を探す」、ルームは「再戦する」「キャラを選び直す」「ルームを出る」。

## 無料枠の見積もり（実測）
- Firestore Spark：読み取り 5万/日、書き込み 2万/日。超えた日はその日だけ使えなくなる（料金は発生しない）。Blaze（従量課金）には切り替えない。
- エミュレーターでの実測（`ranking/` の `npm run test:online`。SDK の呼び出しを数える）：プレイヤー2人の1ターンで **読み取り約8・書き込み5**（技2人分×2件＋計算1件）。マッチングは読み取り約10・書き込み約7。観戦者は1人につき1ターン約3の読み取り（試合ドキュメントの更新3回）。
- 1試合（約7ターン）：観戦なしで読み取り約65・書き込み約42、観戦2人で読み取り約110・書き込み約44。
- **1日あたり約450試合**（書き込みで決まる。観戦が多いと読み取りで決まる）。友達同士の規模なら十分。
- 画面の描き直しのたびに読み直すようなバグが一番危ないので、ターンあたりの回数は `npm run test:online` が毎回表示する。大きく増えていたら調べる。
